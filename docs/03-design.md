# 03-design.md

| 번호/항목 | 선택 | 대안 | 근거 | 트레이드오프 |
| --- | --- | --- | --- | --- |
| 1) 백엔드 | FastAPI | Django, Express | 경량, 비동기 지원, 자동 문서화(OpenAPI), Python 생태계와 통합 용이 | Django 대비 관리자 화면·ORM 등 배터리 포함 기능 부족, 대규모 확장 시 직접 구성 필요 |
| 2) 프론트 | Vanilla JS + Tailwind CDN. API 호출은 상대경로 `fetch("/api/...")` 고정, 절대경로 금지 | React, Vue | 빌드 도구 없이 즉시 실행 가능, 학습/유지보수 부담 최소화, MVP 규모에 프레임워크 오버헤드 불필요 | 컴포넌트 재사용·상태 관리가 프레임워크 대비 수동적이며 규모 커지면 관리 비용 증가 |
| 3) DB | SQLite (SQLAlchemy ORM, 추후 PostgreSQL 전환 고려) | PostgreSQL 즉시 도입 | 설치/운영 부담 없이 로컬 파일 기반으로 MVP 개발 속도 확보, ORM으로 추후 전환 경로 확보 | 동시 쓰기·대용량 트래픽에 취약, 전환 시 마이그레이션 비용 발생 |
| 4) CSS | Tailwind만 사용. styled-components 금지 | - | 단일 스타일링 방식으로 일관성 유지, CDN 방식이라 빌드 파이프라인 불필요 | 유틸리티 클래스 나열로 마크업이 길어질 수 있음 |
| 5) 실시간 | MVP는 폴링 3초 간격. WebSocket은 확장 단계로 보류 | WebSocket 즉시 도입 | 구현 단순, 서버 상태 관리 부담 없음, MVP 요구사항(실시간성 낮음)에 충분 | 폴링 주기만큼 지연 발생, 트래픽 증가 시 서버 부하 |
| 6) 상태관리 | 모듈 변수 + DOM 직접 갱신 | 상태관리 라이브러리 도입 | Vanilla JS 구조와 일치, 별도 의존성 없이 MVP 규모에 충분 | 상태가 커지면 추적/디버깅 어려움, 수동 동기화 필요 |
| 7) 디자인 시스템 | macOS UI 톤. 토큰: `rounded-xl`, `shadow-lg`, `backdrop-blur`, 시스템 폰트 | Material, Ant | 목표 페르소나(팀리더)에게 친숙한 느낌, Tailwind 유틸리티로 바로 구현 가능 | 별도 컴포넌트 라이브러리가 없어 디자인 일관성을 직접 관리해야 함 |
| 8) 테마 | 라이트/다크 토글, `localStorage('theme')`에 저장, 초기값은 `prefers-color-scheme` | 서버 저장 방식 | 로그인 없는 MVP 구조에 적합, 클라이언트만으로 즉시 반영 가능 | 기기/브라우저가 바뀌면 설정이 유지되지 않음 |
